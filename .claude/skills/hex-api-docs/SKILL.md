# hex-api-docs

**Scope:** `infrastructure/http/<name>.api-docs.ts`, one side-effect import in `<module>.module.ts`, response classes named `*.response.ts` only if a return type is a plain `type`. **Out of scope:** editing controllers or DTO decorators. Never add `@Api*` decorators to controllers or DTOs.

## How docs are produced
- **Schemas** (request body, query, response, enums, min/max, required) — generated by the `@nestjs/swagger` CLI plugin at `nest build` (see `nest-cli.json`). Plugin reads classes in `*.dto.ts` / `*.response.ts` and controller signatures in `*.controller.ts`. Plain `type` aliases are invisible to it.
- **Operation metadata** (tag, summary, error responses) — `defineApiDocs` from `@shared/swagger`, applied to the controller from a separate file.
- Swagger UI: `/docs`, JSON: `/docs-json`. Mounted when `NODE_ENV !== 'production'`. **Always `npm run build` first** — `ts-jest`/`ts-node` do not run the plugin.

## Steps
1. **Find targets.** Controllers changed on this branch/working tree: `git diff --name-only main...HEAD; git status --short` filtered to `*.controller.ts`. User may name a controller instead. Nothing found → report "no endpoint to document" and stop.
2. **Collect per handler** (read the controller + the use case it calls):
   - summary: one short imperative line; description only if behaviour is non-obvious (e.g. empty body).
   - `validation: true` if it has `@Body()`/`@Query()` with a DTO class, or a `Parse*Pipe`.
   - errors: every `DomainException` reachable from the handler — use case, domain entities/VOs it calls, repository adapter. For each exception file read the `code` and `EDomainErrorType` from its `super(...)` call. Do not guess codes.
3. **Response types.** If a handler returns a plain `type`/interface, the plugin can't see it: move it to a class in `infrastructure/http/responses/<action>.response.ts` (no decorators, plugin handles it) and change only the controller's import + return type annotation. This is the single allowed controller edit — mention it in the report. `Promise<null>`/`void` needs nothing.
4. **Write `<name>.api-docs.ts`** next to the controller:
```ts
import { EDomainErrorType } from '@shared/domain';
import { defineApiDocs } from '@shared/swagger';
import { AuthController } from './auth.controller';

defineApiDocs(AuthController, {
  tag: 'Auth',
  operations: {
    register: {
      summary: 'Register a new account',
      validation: true,
      errors: [
        { type: EDomainErrorType.CONFLICT, code: 'USER_IDENTIFIER_ALREADY_USED' },
      ],
    },
  },
});
```
   `operations` is typed over the controller's public methods — a missing handler is a compile error. Tag = controller resource in PascalCase.
5. **Import once** in `<module>.module.ts` (skip if present): `import './infrastructure/http/<name>.api-docs';`
6. **Verify:** `npm run lint && npm run build`, then boot `node dist/main` (Postgres up) and check `curl -s localhost:3000/docs-json`: each documented path has the tag, summary, request schema `$ref`, and one response per expected status with the right codes.

## Report
Per endpoint: `METHOD path — summary — statuses (codes)`. Controller edits (step 3), if any. Self-test: `npm run build && npm run start:prod`, open `http://localhost:3000/docs`. Stop.
